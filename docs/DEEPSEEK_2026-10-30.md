# DeepSeek App 接入（2026-10-30）

## 使用

App 底部「AI 助手」→「API 设置 / 测试连接」输入自己的官方 DeepSeek API Key。默认 deepseek-flash，可选 deepseek-v4-pro。留空密钥保存时保留原密钥；删除按钮需另行确认。测试连接发送固定合成文字，校验密钥、实际模型调用及 JSON 返回，而非仅查询模型列表。

1. 整理填表：输入一段问诊笔记，建议拆到主诉、现病史、既往史等文本栏。
2. 润色本段：选择一个已有文本字段，发送该段，保留事实与限定词。
3. 检查病历：根据实际已录资料给出矛盾、缺项和补问，不提供写入操作，也不能证明病历正确或完整。
4. 生成摘要草稿：仅根据已提供事实形成待核对摘要，不自动增加诊断、处方或计划。

统一流程：预览实际发送内容 → 明确同意发送 → 建议/原文/引用对照 → 勾选采纳。已有字段默认不覆盖，另勾允许替换才能覆盖。采纳保存在草稿，仍是 AI 待核对；逐项确认会绑定当前值指纹。原内容可通过撤销恢复，撤销栈只在本次运行中保留。

过敏、吸烟饮酒等选择项不由模型自动改变。可整理为既往史补充，仍应手动确认对应选择项。正式诊断、处方、检查勾选和患者身份字段不在可写白名单中。

## 数据和隐私边界

- 原生 AIKeyStore 用 Android Keystore AES/GCM/NoPadding 加密 API Key；SharedPreferences 只存密文、IV 与模型名。网页脚本只能读取 configured/model；输入密钥的原生对话框禁止截屏和自动填充。
- Key 不写 localStorage、病历 JSON、日志或仓库。原有禁止云备份和设备传输配置继续适用。无共享内置 Key，无网页代理。
- 固定请求 HTTPS 官方 api.deepseek.com/chat/completions，不跟随重定向；不发送聊天历史，不自动复用其他患者上下文。
- 发送字段白名单排除身份栏；对自由文本中的本病历已知姓名、电话、地址、单位、病历号等进行替换，另识别常见手机号及身份证号。屏蔽不保证完全匿名，用户必须检查预览并满足单位的数据使用要求。
- 未核对的模板、默认、示例及既有 AI 字段（含父字段来源）不作为事实发送；空白默认正常查体不发送。实际非空生命体征、已勾选非空体征、检查结果和原录入诊断可作为检查/摘要依据。
- AI 采纳后以 source=ai 保留模型、时间及逐字引用，随病历备份一起保存；不自动升级为已核对。建议使用新版本恢复备份，旧版可能无法识别新的来源类型。
- 原始粘贴笔记只保留在当前助手窗口内存；关闭窗口即清理。采纳后的引用属于病历元数据，会保存在本机。

## 实现

- src/ai-core.js：请求资料整理、身份屏蔽、字段与引用校验、内容基线、采纳边界。
- src/ai.js：App 专用助手窗口、确认发送、对照/选择采纳、原生请求回调、取消/超时、来源核对。
- src/app.js：复用快照撤销、真实异步保存、输出前 AI 待核对提醒。
- src/core.js：增加 ai 字段来源类型，兼容当前 v3 存档；不改存储键。
- MainActivity：仅提供 AI 状态、原生设置、请求、取消接口；退出/销毁关闭连接，返回键先关闭助手。
- DeepSeekClient：非流式完整 JSON 建议，明确等待状态，不宣称逐字流式输出。15 秒连接超时，90 秒读取超时，界面 120 秒总等待取消，256 KiB 响应上限。人工重试，不自动重复计费。
- 请求采用 response_format=json_object，禁用 thinking，max_tokens=4096；只取最终 content，不展示 reasoning_content。finish_reason 必须为 stop，空白、截断、格式错误和非 200 不进入采纳界面。
- 401/403、402、429、5xx 分类提示，不回显服务端原始错误正文；每个进程只进行一个原生 AI 请求。
- 请求结果绑定本地病例 ID 与临床内容指纹；生成期间修改/切换病历，或结果预览后再改内容，均禁止旧结果写入。自动保存单独增加修订号不误判为内容改变。
- 每条建议必须有可逐字匹配的引用、白名单字段且不能重复。阻止无依据数字、时间/单位变化及部分来源、不确定性、否定限定丢失。上述规则是保守筛查，不能可靠识别所有医学语义错误，仍须人工逐字核对。

## 尚未验证

当前环境未配置 DEEPSEEK_API_KEY，也没有从其他应用读取或复制用户密钥。

- 真实 DeepSeek 账户、余额、网络连通与模型端到端调用。
- 真模型对临床合成病例的事实保真、否定/左右侧/药物/单位处理质量、速度、费用和上下文边界。
- 物理 Android 手机输入法、后台长时间恢复、不同系统/WebView 兼容性。
- 本次新增功能对应的新一轮 App 内下载升级全过程（签名/更新机制保持原实现）。

真实验收建议：先在 App 的原生设置保存 Key 并测试，再用“患者诉咳嗽3天，昨晚加重，发热情况未问，既往有高血压，具体用药不详”等合成笔记验证。必须保留未问/不详/患者诉；不要用真实患者资料作为首轮联调输入。

接口依据：[DeepSeek JSON Output](https://api-docs.deepseek.com/guides/json_mode/)、[官方 API 入门](https://api-docs.deepseek.com/quick_start/pricing)、[Android Keystore](https://developer.android.com/privacy-and-security/keystore)。
