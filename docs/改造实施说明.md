# 大病历生成器 v3 改造实施说明

本轮改造对应《大病历生成器改造实施任务书》的五个阶段。代码仍在 `E:\bingli`，未引入新的运行时依赖；所有测试病例均为合成数据。

## 一、总体变化

| 任务书条目 | 实现位置 | 行为变化 |
|---|---|---|
| 2.1 患者资料与文书内容分开 | `src/schema.js`、`src/core.js` | 病历升到 `schemaVersion: 3`，新增 `meta.fieldStates`、`meta.conflicts`、`meta.revision`、`documentMeta`。摘要、首次病程录四段、出院记录入院情况各自记录输入指纹与生成文字指纹。 |
| 2.2 核对状态与内容绑定 | `src/core.js`、`src/app.js` | `fieldStates[path]` 保存 `reviewedValueHash`；内容变化后 `fieldReviewValid()` 返回 false。查体默认描述按“实际会输出的文字”计算指纹。 |
| 2.3 旧数据迁移 | `src/core.js` | v1/v2 存档保留原有文字、诊断、查体勾选和模板标记；来源不明的内容标为 `legacy`，不默认判为已核对；未来版本明确拒绝导入。 |
| 3.1 摘要更新 | `src/app.js`、`src/core.js` | 摘要状态分为空、与资料一致、需更新、人工修改、人工修改且资料已变、已核对、已核对但资料已变、旧存档。过期时给出“现有摘要 / 最新草稿 / 变化组”，可保留原文、采用新草稿、撤销。 |
| 3.2 SOAP 按段更新 | `src/app.js` | S、O（体检）、O（辅助检查）、诊断依据四段各自判断过期，更新一段不影响其他段；手写段不被覆盖。 |
| 3.3 文书时间边界 | `src/schema.js`、`src/core.js` | 首次病程录增加 `soap.recordTime`；出院记录入院情况保存接受草稿时的快照指纹，后续查体变化只提示，不悄悄改写已确认文字。 |
| 4.1 出院诊断单独确认 | `src/generator.js`、`src/app.js` | 出院诊断为空时正文写“待补充”，不再静默回退到初步诊断；提供“从初步诊断带入”，保留“？”等不确定性，带入后仍需单独确认。 |
| 4.2 模板用途分离 | `src/templates.js`、`src/app.js` | 每个模板提供“学习范例”和“患者录入提纲”两个入口。患者录入只展示应问、应查的项目，不写入患者事实。范例模式逐字段记录模板来源与本次带入内容，可查看、可撤销本次带入。 |
| 4.3 默认查体描述 | `src/app.js`、`src/style.css` | 勾选但未填写的查体项显示实际会输出的默认文字和“未核对”角标，可逐项或整组确认；批量确认前列出具体文字。 |
| 4.4 示例生命体征 | `src/app.js` | “填入正常值”改为只展示参考示例，不写入 `pe.vitals`；输出前核对会提示尚未替换的示例值。 |
| 4.5 输出前核对 | `src/app.js` | 生成页顶部列出未核对模板事实、未确认默认查体、过期摘要/SOAP、未确认出院诊断，并可定位到字段。复制仍允许，复制的是草稿。 |
| 5.1 婚姻状态统一 | `src/core.js`、`src/generator.js` | `basic.marital` 为唯一来源。旧数据两处一致时合并；不一致时保留两个原值并提示选择。生成器只读统一值。 |
| 5.2 年龄统一 | `src/age.js` | 新增公共年龄解析：支持纯数字、“岁”、月龄、日龄、周龄；有出生日期和入院/记录日期时按日期计算，不随电脑当天日期漂移；列表、导入预览、生成正文、科室校验共用。 |
| 5.3 病史去重 | `src/generator.js` | 跨病史栏目的完全相同整句在生成时只输出一次；同一栏内重复保留并提示；否定/肯定、左右侧、时间进展不合并；查体不参与整句去重。 |
| 5.4 减少抄写 | `src/app.js`、`src/generator.js` | 辅助检查只录一次，摘要与 SOAP 从同一列表读取；系统回顾仍由用户决定是否标记，不自动把未问项设为阴性。 |
| 6.1 存储异常 | `src/core.js`、`src/app.js` | 读取、写入、删除、JSON 损坏、结构非法、容量不足都有返回值而不是抛到界面；启动失败显示横幅，不白屏；内存内容保留，可导出损坏原文；写入失败不显示“已保存”。 |
| 6.2 草稿与列表 | `src/app.js` | 导出备份时询问是否包含当前最新草稿；选择包含时备份带 `includesDraft: true`；切换病历前保存失败则保留当前内容和位置。 |
| 6.3 多标签页冲突 | `src/core.js`、`src/app.js` | 每次保存递增 `meta.revision`；保存前比对修订号，冲突时暂停写入并提示“载入新版本 / 保留为副本”；不同病历互不影响。 |
| 6.4 撤销 | `src/core.js`、`src/app.js` | 内存快照栈按病历 ID 绑定，默认上限 20；覆盖摘要更新、SOAP 分段更新、模板带入、查体批量确认、导入替换前恢复副本。撤销历史只在本机内存。 |
| 7.1 结构化校验 | `src/generator.js`、`src/app.js` | 新增 `validateStructured()`，返回 `code / severity / document / paths / message / action`；`validate()` 仍返回字符串数组以兼容旧调用。提醒可定位到字段。 |
| 7.2 手机输入 | `src/app.js`、`src/style.css` | 输入事件继续局部刷新，不整页重绘；窄屏下按钮撑满、差异区可滚动；提醒跳转后返回原步骤。 |
| 7.3 离线与版本 | `sw.js`、`src/app.js`、`src/index.html` | 在线版注册 Service Worker，首次准备完成后提示可离线；新版本提示但不在编辑中强制刷新；页脚显示应用版本；`file://` 本地 HTML 不依赖 Service Worker。 |

## 二、数据模型

```js
{
  schemaVersion: 3,
  id: "r...",
  meta: {
    revision: 0,
    updatedAt: "",
    fieldStates: {
      "pe.general.face": {
        source: "default",        // manual | template | default | generated | legacy
        reviewed: true,
        reviewedValueHash: "",
        sourceRef: ""
      }
    },
    conflicts: {
      marriage: { basicValue: "", marriageValue: "", resolved: false, chosen: "" }
    },
    migratedFrom: 2,
    migrationNotes: [],
    lastTemplateFill: null
  },
  documentMeta: {
    summary: { origin, inputGroups, inputFingerprint, generatedTextHash, reviewedFingerprint },
    firstCourse: {
      s: {}, oPe: {}, oAux: {}, basis: {}
    },
    discharge: {
      admitCondition: {},
      diagnoses: { origin, inputFingerprint, textHash, confirmed, confirmedFingerprint }
    }
  }
}
```

指纹使用键排序后的稳定序列化 + FNV-1a，只用于判断资料是否变化，不作为安全机制。

## 三、兼容边界

- `validate()` 的字符串返回值保持不变；新代码可用 `validateStructured()`。
- `ageWithUnit({ age: '7月' })`、`ageYears({ age: '14日龄' })` 等只传 `basic` 对象的旧调用保持原行为；传入整份病历时才启用出生日期换算。
- `marriage.status` 仍被生成器作为回退读取，以兼容旧测试和旧存档；迁移后正常路径只写 `basic.marital`。
- 旧存档没有 `documentMeta` 时，已有摘要/SOAP 文字标为 `legacy`，保留原文并允许与新草稿比较，不判为已核对。
- `schemaVersion > 3` 的存档在导入和读取时明确拒绝，当前数据不被覆盖。

## 五、未完成与未验证

- Android 真机未测试：中文输入法组合输入、软键盘遮挡、后台恢复、真实触控目标大小只做了代码与窄屏样式检查。
