# 验收用例（A01–A20）

运行方式：

```bash
node build.js
node --test tests/*.test.cjs
npm run verify
```

自动化覆盖文件：

- `tests/new-behavior.test.cjs`：数据模型、摘要/SOAP 状态、出院诊断、年龄、去重、模板、存储、冲突、导出、撤销。
- `tests/app.test.cjs`：真实产物里的界面动作（摘要更新/撤销、出院诊断带入、查体确认、模板患者模式、列表年龄、输出核对）。
- `test/browser-check.js`：headless Chrome 真实点击。
- `test/file-scenario.js`：`file://` 场景。
- `test/online-check.js`：线上地址检查（需部署后复测）。

## 三、未覆盖 / 未验证

1. **Android 真机**：中文输入法组合输入、软键盘遮挡、后台恢复、触控目标、长文选中复制均未在真机执行。仅做了代码路径和窄屏样式检查。
2. **真实双标签页**：多标签页冲突用单元测试和 storage 事件桩验证，未在两个真实浏览器标签页中手动复现。
3. **Service Worker 离线重启**：只在本地静态服务器和 headless Chrome 验证注册/缓存，未在手机浏览器断网重启验证。
4. **线上部署**：构建已同步根 `index.html` 与 `dist/大病历生成器.html`，但当前线上地址仍是旧产物；部署后需重跑 `test/online-check.js`。
5. **真实历史备份**：迁移测试使用合成 v1/v2 样本，未覆盖用户全部历史备份变体。
6. **界面联动细节**：婚姻状态两个入口已统一到 `basic.marital`，提醒跳转后返回位置由 `jumpToPath` 处理；仍缺真实触屏逐项回归。

5. 用合成病例走 A01–A20，重点手测 A10、A12、A14、A17、A18。
