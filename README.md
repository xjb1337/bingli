# 大病历生成器

一个**离线、单文件**的网页工具，帮你在手机上把问诊和查体的内容整理成一份规范的大病历。
不用联网、不用装 App、数据只存在你自己手机里。

---

## 一、怎么放到手机上

### 方法 1：直接传到手机（推荐，最简单）

1. 把 `dist/大病历生成器.html` 通过**微信文件传输助手 / QQ / 数据线**发到安卓手机；
2. 在手机上用**文件管理**找到它，点击 → 选择用 **Chrome（推荐）** 或 Edge 打开；
3. 打开后点浏览器菜单 → **添加到主屏幕**，以后就像 App 一样一点即开。

> iPhone 也可以用（用 Safari 打开），同样支持"添加到主屏幕"。

### 方法 2：电脑上先用

双击 `dist/大病历生成器.html` 即可在电脑浏览器中使用，界面对手机优化，电脑上会显示为窄栏。

## 二、填写流程

顶部有 11 个步骤，按顺序填，几乎全部是**点选**，只有主诉、现病史需要打字。

| 步骤 | 内容 | 要点 |
|---|---|---|
| ① 基本情况 | 姓名、性别、年龄、**科室**、主诉 | **先选科室**，后面查体会自动带出该科专科查体 |
| ② 现病史 | 起病、症状特点、进展、伴随、诊治经过、一般情况 | 可点"一键生成初稿"再改 |
| ③ 系统回顾 | 12 个系统、90 个症状 | 默认全阴性，**有症状的点一下变红**即阳性 |
| ④ 既往史 | 慢性病、传染病、手术外伤、过敏 | 手写"疾病详情"会优先于勾选 |
| ⑤ 个人史 | 出生地、吸烟饮酒、接触史 | 吸烟选"有"后填具体量 |
| ⑥ 婚育史 | 婚姻、月经、生育 | 女性才出现月经史 |
| ⑦ 家族史 | 家族疾病 | |
| ⑧ 体格检查 | 生命体征 + 通用查体 + **本科室专科查体** | 每项都有"常用描述"快捷选项 |
| ⑨ 辅助检查 | 检查项目和结果 | 可加多行 |
| ⑩ 摘要与诊断 | 质控提醒、诊断参考提示、初步诊断、病历摘要 | 提示仅作参考，需自己判断 |
| ⑪ 生成病历 | 全文预览、复制、下载 | |

### 几个省时间的设计

- **主诉实时预览**：填完症状和时长，下面立刻显示"发热、咳嗽、咳黄痰3天。"，不用自己拼。
- **生命周期体征**：点"填入正常值"一键填 36.5 / 78 / 18 / 120/80，再改异常项。
- **BMI 自动算**：填了身高体重，自动显示 BMI 和胖瘦分级。
- **查体快捷描述**：每个查体下面"常用描述"里点一下即可替换默认正常描述。
- **质控提醒**：会提示"主诉含诊断性词语""主诉超过20字""初步诊断未填"等。

## 三、导出与保存

- 点右上角 **复制**（在生成页）→ 粘贴到微信、备忘录或医院的电子病历系统；
- 点 **下载 .txt** → 存成文本文件；
- 点 **复制某段** → 只需要"现病史"或"体格检查"时单独复制；
- 点 **保存** → 存进本机，右上角 **病历** 可查看、切换、删除历史病历；
- 点 **病历 → 导出备份** → 存成 `.json` 文件，这是**唯一可以用来换手机/找回数据**的方式；
- 点 **病历 → 导入备份** → 支持合并（保留现有、同 ID 取较新）或替换。

> ⚠️ 数据保存在**当前浏览器**里。不要在浏览器设置里清"网站数据"，否则记录会丢。
> 换手机、重装浏览器前，**必须先导出备份**并保存到手机外（微信收藏、电脑）。
>
> 如果保存失败（存储空间满或隐私模式），页面顶部会显示红色告警，**不会假装保存成功**。
> 如果本地存档损坏，工具会保留原始数据不覆盖，并提示你先备份。

## 四、诊断参考提示怎么用（重要）

第 ⑩ 步的"诊断参考提示"是**根据你填的阳性发现自动匹配的清单**，作用是提醒你不要漏掉需要鉴别的疾病。

- 它**不会自动写入**病历，只有你点"加入诊断"才会加进去；
- 它**可能误报或漏报**，只是辅助记忆，不能代替你的判断；
- 提示里附带的"可补充：…"是建议进一步做的检查，供你参考。

请始终以自己的临床判断和带教老师的意见为准。

## 五、几个常见问题

**Q：换手机 / 换浏览器，数据还在吗？**
不在。数据存在打开它的那个浏览器里。换设备请用"下载 .txt"迁移。

**Q：能填好几个病人吗？**
可以。点右上角"病历"→"新建病历"。

**Q：科室选错了怎么办？**
回第 ① 步改，第 ⑧ 步的专科查体会跟着变（已填的通用查体内容不会丢）。

**Q：生成的文字不满意？**
每个查体项都是可编辑文本框，直接改；主诉、现病史也一样。你写的优先，工具只做拼接。

**Q：会不会把数据传出去？**
不会。整个工具是单个 HTML 文件，不联网、不发请求，没有服务器。

## 六、目前支持的科室

通用/全科、呼吸内科、消化内科、心血管内科、内分泌科、肾内科、血液内科、
神经内科、外科（普外/骨科等）、产科、妇科、儿科、急诊/ICU。

每个科室除了通用查体，还会追加 1–5 项该科室的专科查体
（如神经内科的高级神经活动、颅神经、运动/感觉系统、共济运动）。

### 测试

单元测试不依赖浏览器和第三方库，全部用 Node 内置的 `node:test`：

```powershell
node build.js                      # 先构建
node --test tests/*.test.cjs       # 全部单元测试（135 项，约 0.2 秒）
npm run coverage                   # 只看核心逻辑的覆盖率
```

| 测试文件 | 覆盖内容 |
|---|---|
| `tests/core.test.cjs` | 存档迁移、损坏保护、原型污染、导入导出、合并策略（46 项） |
| `tests/generator.test.cjs` | 13 个科室章节完整性、专科查体隔离、婚育史分支、否定表述、质控规则（61 项） |
| `tests/app.test.cjs` | 沙箱内跑真实产物：保存失败可见、损坏不覆盖、旧病历补字段（14 项） |
| `tests/artifact.test.cjs` | 产物与源码逐行比对，防止改了源码忘记重新打包（14 项） |

### 几个关键约束（改代码时请守住）

1. **改任一 `src/` 文件后必须 `node build.js`**，否则手机拿到的是旧代码。
   `tests/artifact.test.cjs` 会逐行比对产物与源码，忘记构建会直接测试失败。
2. **存储与数据校验只能写在 `core.js`**，不要写进 `app.js`。
   这样边界行为（存档损坏、存储写满、导入恶意 JSON）才能被单测覆盖。
3. **保存失败绝不能提示"已保存"**。写完后要检查返回值，失败时显示顶部告警。
4. **损坏的存档不得静默覆盖**。读取失败时原数据必须原样保留。
5. 新增科室：改 `schema.js` 的 `PE_SPECIAL` 和 `DEPARTMENTS`，再跑 `npm run verify`。
6. 新增诊断提示：改 `hints.js` 的 `RULES`，`must` 是必须命中的条件，能有效减少误报。

### 文件命名约定

`src/` 是源码，`dist/` 是产物，**不要手改 `dist/`**——它每次都会被打包覆盖。
