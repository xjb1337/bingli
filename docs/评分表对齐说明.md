## 0. 这份文档怎么用

1. **先看第 1 章**搞清「两类评分要素」——这是全文最关键的判断，决定了某个要素该不该进 `record`、该不该进病历正文。

### 1.2 当前产出结构（`GENERATOR.SECTION_ORDER`）

```
一般项目 / 主诉 / 现病史 / 既往史 / 系统回顾 / 个人史 / 婚育史 / 家族史
/ 体格检查 / 辅助检查 / 病历摘要 / 初步诊断     —— 共 12 节
```

即：产出的是**入院记录（大病历）**，没有首次病程录、没有病程记录、没有上级医师查房、没有出院记录。
对照评分表：考站四「病历书写」100 分里，入院记录只占 **25 分**，另外 **75 分**（首次病程 20 + 病程记录 35 + 上级查房 5 + 出院记录 15）目前**完全没有载体**；考站三「首次病程录」100 分**整站未覆盖**。

### 1.3 两类评分要素（**先分清，后面所有判断都基于此**）

| 类型 | 定义 | 处理方式 | 举例 |
|---|---|---|---|
| **A 类：病历文本要素** | 必须写进病历、可被考官在纸面上核对的 | 进 `record` 字段 → 进 `generator` 正文 → 进 `checker` 打分 | 现病史要写诱因/缓解因素；查体阴性体征；诊断依据 |
| **B 类：过程/沟通要素** | 评的是「考生做了什么动作」，病历纸面上**不出现** | 进 `record.exam`（应试自查区，**不并入病历正文**）；`checker` 只做「是否自评过」的提醒 | 检查者自我介绍 2 分；问诊技巧 18 分；医患沟通 22 分；查体手法 2 分 |

> ⚠️ **这是本项目最重要的边界**：评分表里共 **49 分**属 B 类——病史采集的自我介绍 2 + 问诊技巧 18 + 医患沟通 22 + 体格检查的查体准备 2 + 整体评价 5；若再把「重点查体」15 分里偏过程性的「手法/思路」部分算进来，接近 64 分。这些**绝不能塞进病历正文**，否则生成的大病历会出现「检查者自我介绍：张三，住院医师」这种不该出现在病历里的句子。
> 因此**不要**把 `exam` 的任何字段接进 `SECTION_ORDER`。

### 3.7 ★ 腹部查体次序缺陷专项

#### 3.7.1 评分表要求（第 3 页原文）

> 腹部（20 分。**腹部检查次序正确得 2 分**；动作手法不正确，每次扣 1 分）
> （视诊）腹部形态 2
> （听诊）肠鸣音（听诊部位正确并口述听诊时长，每项 2 分）4
> （叩诊）常规按逆时针次序叩诊（不要求脾区叩诊）4
> （触诊）全腹浅触诊和深触诊（须关注患者压痛反应，每项 2.5 分），肝、脾触诊（每项 2.5 分）10

即标准次序：**视诊 → 听诊 → 叩诊 → 触诊**。
医学原理：触诊和叩诊会刺激肠管、改变肠鸣音，所以腹部听诊必须在触诊、叩诊**之前**完成。这是内科查体的硬规范，也是评分表单列 2 分的原因。

#### 3.7.2 当前实现（错误）

`src/schema.js:415-443`，`PE_COMMON` 中 `key: 'abdomen'` 的 `items` 顺序为：

```js
// 当前（错误）—— schema.js:417-442
items: [
  { key: 'abdInspect',      label: '视诊', ... },   // ① 视诊
  { key: 'abdPalpation',    label: '触诊', ... },   // ② 触诊  ← 错位
  { key: 'abdPercussion',   label: '叩诊', ... },   // ③ 叩诊
  { key: 'abdAuscultation', label: '听诊', ... }    // ④ 听诊  ← 错位
]
```

生成结果印证（`samples/呼吸内科_社区获得性肺炎.txt:38`）：

```
腹部：腹平软，未见腹壁静脉曲张。全腹无压痛、反跳痛，未触及包块，肝脾肋下未触及。
      肝区及双肾区无叩击痛，移动性浊音阴性。肠鸣音正常，约4次/分。
```

顺序为 **视 → 触 → 叩 → 听**，与评分表**相反**，且违反「听诊先于触叩」的临床规范。

#### 3.7.3 差异与影响

| 项 | 评分表要求 | 当前实现 | 影响 |
|---|---|---|---|
| 腹部次序 | 视诊 → **听诊** → 叩诊 → **触诊** | 视诊 → **触诊** → 叩诊 → **听诊** | ①「腹部检查次序正确得 2 分」直接丢 2 分；②生成的病历**教坏了使用者**，按此顺序实操会被扣分；③`checker` 若按 schema 声明顺序校验，会把错误当成正确 |

#### 3.7.4 修正方案（可直接照改）

```js
// src/schema.js  PE_COMMON → key:'abdomen' → items 顺序调整为：
items: [
  { key: 'abdInspect',      label: '视诊', ... },   // ① 视诊：腹部形态
  { key: 'abdAuscultation', label: '听诊', ... },   // ② 听诊：肠鸣音（必须在触叩之前）
  { key: 'abdPercussion',   label: '叩诊', ... },   // ③ 叩诊：逆时针
  { key: 'abdPalpation',    label: '触诊', ... }    // ④ 触诊：浅/深/肝/脾
]
```

**约束（改错就白改）**：

1. **只调腹部**。胸部仍是「视诊→触诊→叩诊→听诊」（评分表胸部未要求特殊次序，第 3 页胸部行文即为视触、叩、听），心脏同。**不要把「听诊提前」这条规则推广到胸部**。
2. **`key` 名一个都不能改**：`abdAuscultation` 被 `hints.js` 的 `pev:abdomen.abdAuscultation=…` 引用；`abdPalpation` 被 5 条规则引用（含阑尾炎 `must`）。
3. `generator.buildPE`（第 382–390 行）是按 `group.items` 顺序 map 的，**不需要改**，改 schema 即自动生效。
4. 验收断言（t2 的 verify 已写死）：
   ```js
   const abd = require('./src/schema.js').PE_COMMON.find(g => g.key === 'abdomen');
   abd.items[0].key === 'abdInspect' && abd.items[1].key === 'abdAuscultation'
   ```
5. 建议同时补一条生成器/测试断言：`GENERATOR.buildPE(r)` 的腹部段落里，`肠鸣音` 的位置下标 < `压痛` 的位置下标。这是**变异自检**的要求（t6 会把顺序改回错的，必须挂测试）。
